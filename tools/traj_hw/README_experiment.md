# 硬件轨迹跟踪实验说明

目标：把论文中仿真的轨迹跟踪图升级为实测。FPGA 阻抗链在环（host-in-the-loop）：
实验机 host 经 CAN 实读关节角 → UDP op2 写 q / op10 写 x_des → FPGA 计算 → host 读回下发驱动。

轨迹：xy 平面圆 r = 111.8 mm × 3 圈 + z 相对爬升 +100 mm，共 60 s，
五次多项式时间标度（起停处速度、加速度为零，平滑起步），姿态全程保持恒定。
数值口径全程 Q16.16（米 / 弧度）。

## 1. 文件清单

| 文件 | 用途 |
|---|---|
| `traj_xdes_delta.csv` | 增量轨迹表，100 Hz × 60 s = 6001 行（实验机用） |
| `traj_analyze.py` | 跑完后的分析出图脚本（拿回本仓库所在机器跑） |
| `gen_traj.py` | 轨迹表生成脚本（存档 / 复现用，实验机不用跑） |

## 2. 锚点做法（关键）

表里存的是**相对增量 Δ(t)**，不是绝对位姿：

1. 开跑前经 CAN 实读当前 6 关节角 `q_start`；
2. `op2` 写 `q_start` → `op8` 读回起始位姿 `p0`（24B，Q16.16；或 host 自算 FK 得 p0，与 FPGA 同口径即可）；
3. 每个控制周期取表中当前行，`x_des(t) = p0 + Δ(t)`（表后 6 列与 p0 逐分量 **Q16.16 整数相加**），经 `op10` 下发；
4. `Δ(0) = 0`，所以第一拍 `x_des = p0`，无跳变平滑起步；姿态三轴增量恒为 0，即保持起始姿态。

## 3. 日志契约（分析脚本按此解析，原文照抄）

每行 `t_ms, q0_q16..q5_q16, xd0_q16..xd5_q16`（可含表头行，健壮解析；xd 为 host 实发的绝对 x_des）。

- `t_ms`：真实毫秒时间戳（从开跑起算）；
- `q*_q16`：CAN 实读的关节角，Q16.16 弧度；
- `xd*_q16`：当拍实际下发的**绝对** x_des，Q16.16（前 3 列米，后 3 列弧度）。

采样率跟 host 循环走、记真实 `t_ms` 即可，50–200 Hz 均可，不必恰好 100 Hz。

## 4. 建议流程

1. **空跑核对**：不使能驱动，完整跑一遍循环并记录 `x_des`，核对幅度——xy 半径约 111.8 mm、
   z 终点相对爬升 +100 mm、起点无跳变；
2. **实跑**：使能驱动，跑满 60 s，按第 3 节契约存 `log.csv`；
3. **分析**：把 `log.csv` 拿回本仓库所在机器，执行

   ```
   python tools/traj_hw/traj_analyze.py log.csv
   ```

   在日志同目录得到 `traj_xy` / `traj_xyz_t` / `traj_err_t` 三组 png+pdf，
   终端打印全程与稳态段（t>5s）的逐轴 + 欧氏 RMS/max（mm），末行 sentinel `TRAJ_ANALYZE_OK`。

## 5. 安全

首圈全程盯住机械臂，急停握在手边，有异常立即停。
